# D4 model specification (frozen)

Generated by `src/model/09_final_refit.py` (via `src/model/spec_writer.py`); do not edit by hand. This is the contract for the D4 builder: what the deployed model is, exactly how to feed and read it, and how to prove the deployment matches the local build.

## 1. Status

- Model: gradient-boosted trees (`HistGradientBoostingClassifier`), label `exit_12m` (primary label, batch-end exits included), refit on cohorts **2012-2021** (21,330 store-years, 857 exits: 2012-2018 14,982/632, 2019-2021 6,348/225).
- Settings, features, calibration decision and tier cutoffs are frozen; nothing was re-tuned or re-selected on validation (`docs/changes_since_d3.md`).
- **The refit model can no longer be evaluated on validation** (validation is now inside its training data). Its only evaluation is the single D6 run on the reserved test cohorts 2022-2024, which have never been read. Every performance number quoted in this spec comes from the **2012-2018 model** (same settings) scored on validation 2019-2021, and is evidence about the settings, not about this fitted model.
- Rebuild: `uv run python src/model/09_final_refit.py` (needs the prep scripts through `05d_context_columns.py`). The model file is deterministic: rebuilding gives identical `docs/model_examples_d4.json`.

## 3. Features and raw inputs

The model takes exactly these 20 columns, in this order, all known on Jan 1 of the cohort year t (hard rule 2; definitions and timing in `docs/data_dictionary.md`). `year`, every `qa_*`, `impact_*`, `exit_*`, `bias_*` column, raw end dates and the `context` column are **not** inputs. Calendar year is not an input in any form.

| # | Input | Raw source | Units / handling | Used by the 300 stumps |
|---|---|---|---|---|
| 1 | `store_type` | USDA SNAP Retailer Locator `Store Type` | one of Supermarket, Super Store, Large Grocery Store, Medium Grocery Store, Small Grocery Store; categorical, no other value accepted | yes |
| 2 | `store_age_years` | authorization date of the store's current spell | years from the spell's authorization date to Jan 1 of t; missing for the USDA placeholder date 1/1/1930 (left missing: HGB's native missing branch) | yes |

| 5 | `n_prior_ownership_changes` | spell table (03_spells) | count of ownership transfers in the store's lineage that ended before Jan 1 of t | yes |

| 17 | `pct_snap_hh` | ACS 5-year B22001 | share 0-1 of households | yes |

| 19 | `pct_age_65_plus` | ACS 5-year B01001 | share 0-1 of tract population | yes |
| 20 | `unemployment_rate` | ACS 5-year B23025 | share 0-1 of the civilian labor force; missing for the 2012 cohort and imputed (see below) | yes |

The stumps split on 16 of the 20 inputs; unused: `auth_date_placeholder`, `n_prior_spells_same_id`, `n_grocery_1mi`, `n_grocery_ends_1mi_prior12m`.

### Input preparation (done by `Bundle.prepare`)

1. **`median_hh_income` is a within-year percentile.** Nominal income drifts across ACS vintages, so the model sees the tract's income percentile among all grocery store-years of the same cohort year (`pandas.DataFrame.groupby('year')['median_hh_income'].rank(pct=True)`, average ties; `serving.income_percentile_within_year`). The percentile must be computed over **every grocery store-year of that cohort**, not over the rows being scored; a single store therefore needs its cohort's income distribution (for stores already in the Supabase `store_year` table, compute the rank over the table's rows of that year).
2. **`unemployment_rate` is imputed with the median of the refit rows, 0.08414766558089033**, when missing (it is missing for the whole 2012 cohort). A NaN would let a tree isolate 2012, a calendar-year proxy that project rules forbid.
3. **`store_type`** is cast to a pandas category with the stored categories `Large Grocery Store`, `Medium Grocery Store`, `Small Grocery Store`, `Super Store`, `Supermarket`; any other value is rejected (`ValueError`).
4. All other inputs are cast to float. Missing values elsewhere (`store_age_years`, ACS columns, `pop_density_sqmi`, neighbour counts without coordinates) use HGB's native missing-value branch, exactly as in training.

## 4. Calibration: none applied

The raw probabilities are used as they are. Evidence (2012-2018 model, validation 2019-2021, `docs/calibration.md`): mean predicted 3.48% vs observed 3.54% (ratio 0.98), calibration slope 1.26, Brier 0.0321. The rule fixed before looking (miscalibrated if the ratio is outside 0.8-1.25 or the slope outside 0.7-1.3) was not met. A Platt calibrator fit on training folds only (out-of-fold 2015-2018) would not have helped (Brier 0.0321 -> 0.0322, mean predicted 3.48% -> 3.79%). Known weak spot: the lowest four deciles had observed exit rates of 0-0.16% against predicted 0.6-1.3%, i.e. the model over-predicts for the safest stores. Show probabilities as estimates (e.g. 'about 15%'), not exact figures.

## 5. Risk tiers

Cutoffs on the raw probability: **low < 0.021; medium 0.021 to < 0.084; high >= 0.084** (0.5x and 2x the 2012-2018 base rate of 4.22%; chosen on validation by rules fixed in `src/model/06_risk_tiers.py`, `docs/risk_tiers.md`). They stay fixed for the refit model, which was checked first: tier shares moved by at most 2.3 percentage points against the 2012-2018 model on matched rows (rule: < 5; `docs/refit_tier_shares.md`). Refit model on all 2012-2021 rows: low 47.1%, medium 40.0%, high 12.9%.

Observed exit rates by tier (2012-2018 model on validation 2019-2021; the cutoffs were chosen on these data, so read them as optimistic; training out-of-fold 2015-2018 is the independent check):

| Tier | Validation store-years | Validation exit rate | Out-of-fold exit rate |
|---|---|---|---|
| low | 2,973 (46.8%) | 0.3% | 1.4% |
| medium | 2,728 (43.0%) | 4.3% | 4.1% |
| high | 647 (10.2%) | 15.5% | 14.4% |

Expect the low tier to run nearer 1% than 0.3% on new data. Tier shares will drift with the cohort mix; do not retune cutoffs on test.

## 6. Explanations

**Method.** With `max_leaf_nodes=2` every one of the 300 iterations is a stump that splits on one feature and returns one of two leaf values (already scaled by the learning rate). The raw score (log-odds) is exactly `baseline + sum of per-feature contributions`, baseline = -3.173424305254799, where a feature's contribution is the sum of the leaf values of the stumps that split on it. `explain.contributions` obtains each stump's value from the stump's own predictor (the call HGB's `_raw_predict` makes), so it needs no re-implementation of thresholds, missing-value direction or category bitsets; it therefore uses scikit-learn internals (`_predictors`, `_preprocess_X`, `_bin_mapper`) and is only valid for the pinned version. Verified to ~1e-14 on all 21,330 refit rows and on every example.

**Reasons.** Contributions are centred at the average refit-row store (`reference_contributions`, stored in `bundle.json`); a reason is one of the three features with the largest **positive** centred contribution ('raises risk relative to a typical store'). Fewer than three are returned when fewer features exceed the average. Text comes from the phrase table in `explain.PHRASES` (value-aware, e.g. 'It is a Small Grocery Store (raises risk)').

**Display rule (decided): explanations are shown only for medium and high tier stores.** Low-tier rows get no reasons (`display_reasons` returns an empty list): their effects are a few hundredths of a log-odd and read as noise. Reasons describe what the model uses, not causes; chain size and store type dominate (mean |contribution| on validation 0.65 and 0.50 log-odds) and they differ systematically between tracts (see the bias finding in `docs/changes_since_d3.md`).

## 7. Impact score and ranking

**Impact** (decided; weights fixed before any result and not tuned): `impact = 0.50 x rank(dist_other_grocery_jan1_mi) + 0.25 x rank(pct_snap_hh) + 0.25 x rank(pct_no_vehicle)`, in (0, 1]. `dist_other_grocery_jan1_mi` is the prep-pipeline column (`05d_context_columns.py`, role **`context`**: Jan-1 information used only for this score, never a model input): miles to the nearest other grocery-type authorization active on Jan 1 of t, own Record ID excluded. Each rank is a percentile (midpoint of ties) against the pooled 2012-2021 store-year reference stored in `impact_reference.json` (21,330 store-years). Missing tract values get rank 0.5; missing distance gets rank 0.5; no other grocery at all (infinite distance) gets rank 1. Note that `pct_snap_hh` and `pct_no_vehicle` enter the impact score as raw tract shares even though the risk model also uses them.

**Ranking.** `priority = predicted probability x impact`. **The app defaults to ranking by priority (risk x impact) and offers an option to rank by risk alone.** Tiers and reasons always come from risk, never from priority.
Validation evidence (2012-2018 model, report only, `docs/impact_score.md`): top 50 per year statewide, risk alone caught 38 exits (8 of 44 'gap' exits, i.e. no other grocery within a mile at exit); risk x impact caught 31 exits (14 gap exits); 69 of 150 flagged store-years are common to both lists; the priority list shifts toward isolated rural small stores. In Mecklenburg the top 10 per year caught 8 exits either way. These are descriptive counts on 150 flags, not a test.

## 8. Environment pin and startup self-check

- **Pin the exact versions the bundle was built with: `scikit-learn==1.9.1`** (also built with Python 3.13.5, numpy 2.5.4, pandas 3.1.0, scipy 1.18.1, joblib 1.6.0). The pickle and the explanation code depend on scikit-learn internals, so a different version must not be served even if it loads. Pin it in the Modal image (`pip_install('scikit-learn==...')`), not just in `uv.lock`.
- **At startup the API runs `Bundle.self_check()` and answers `503` on every scoring route until it passes** (and on `/health` reports the failure messages). The check fails if (1) the installed scikit-learn is not the pinned version; (2) on any fixed example `baseline + sum(contributions)` differs from the raw score by more than 1e-09; or (3) any example's raw score, probability, impact or priority differs from the stored expected value by more than 1e-09, or its tier or reasons differ. Check (3) is the local-versus-deployed match; check (2) is the explicit sum identity.
- The self-check was tested here: it passes on the freshly built bundle in a clean interpreter (`python -I`), and fails on a perturbed expected probability and on a wrong pinned version.

## 10. Limits the D4 app must state

- Estimates a store's chance of **losing SNAP authorization within 12 months of Jan 1**, with ownership changes not counted as exits and administrative batch ends counted as exits (`exit_12m`). It does not say a store will close.
- Discrimination is modest: 2012-2018 model validation PR-AUC 0.149 against a 3.5% exit rate; top-50-per-year precision 25%. Say 'higher risk', not 'will exit'.
- Fairness: dropping the seven tract demographic inputs did not narrow the majority-Black vs majority-White false-positive gap (4.1% vs 1.5% with them, 4.6% vs 1.2% without, validation, top 50 per year); it is plausibly carried by store type and chain size. To be reported on the test set in D6 (`docs/changes_since_d3.md`).
- The 2022-2024 cohorts have never been scored. The refit model's only evaluation is the D6 test run.
