# Changes since D3 (start of D4)

The `d3` tag is frozen. These are new commits on `main`. Results are regenerated by `src/model/01_evaluate.py`
then `src/model/02_error_analysis.py` (one rerun). "D3" below is the `d3` tag (`git show d3:docs/model_results.csv`).
The D3 error-analysis comparison uses the trees rows added in commit 78064de, because the tagged error analysis
had no trees rows.

## What changed

1. **Year-proxy indicator removed.** `unemployment_rate` is missing for the whole 2012 cohort and almost
   nowhere else (0.0-0.1% in 2013-2019), so the logistic regression's missing-value indicator for it marked
   "cohort 2012". Both models now median-impute `unemployment_rate` first (`ImputeUnemployment` in `01_evaluate.py`,
   fitted on the training rows of each fit only: inside each tuning fold, and on 2012-2018 for the final fit).
   The other missing indicators are unchanged. **Trees:** yes, the same issue applied (a NaN branch isolates 2012
   exactly), so the trees get the same imputation. A residual caveat: the imputed 2012 rows share one constant
   value, which a tree could in principle still isolate with narrow splits; `min_samples_leaf` makes that hard
   but not impossible.
2. **Tuning grids widened.** Logistic regression `C`: 0.01-10 plus 30, 100 and 1e6 (essentially unregularized).
   Trees: first pass lr 0.01-0.1, leaves 4-16, min_leaf 40-100, l2 0-1. That pass (training folds only) put the
   `exit_12m` trees at min_leaf 40 / l2 1.0 and the strict trees at lr 0.01, leaves 4, min_leaf 100, l2 0, all
   edges, so the grid was widened once more: lr {0.003, 0.01, 0.03, 0.1}, leaves {2, 4, 8, 16}, min_leaf
   {20, 40, 100, 200}, l2 {0, 1, 10}. Settings are chosen by mean rolling-fold PR-AUC inside 2012-2018, as in D3.
   Validation was scored once, in the final run. `max_iter` stays 300 for all trees.
3. **Not changed: `n_prior_ownership_changes`.** A store-year row exists only if the store is authorized on
   Jan 1 of t, so any ownership-change link followed from that row (successor = this spell) was already
   authorized by Jan 1. The feature therefore uses no information from after Jan 1, and requiring the 90-day
   window to have closed would drop real, known transfers. `05_features.py` is unchanged and not rerun.

## Feature additions (pre-registered)

Written and committed **before any of these features was built or scored**, so the history shows the plan came
before the results. The `d3` tag stays at f0fa11f; work is on `main`. Current selected model: gradient-boosted
trees (lr 0.1, max_leaf_nodes 2, min_samples_leaf 100, l2 0, 300 iterations), fold PR-AUC 0.155, validation
PR-AUC 0.149 (`exit_12m`).

### Candidate features and timing rules

All four use only information available before Jan 1 of cohort year t, computed by the same code for the
train/validation and test panels. Each gets an assertion in the pipeline.

1. **`n_bigstore_openings_2mi_prior12m`**: count of Supermarkets and Super Stores within 2 miles of the store
   whose authorization began in [Jan 1 t-1, Dec 31 t-1] (strictly before Jan 1 t), excluding ownership changes
   (an opening whose spell is the successor of an earlier record) and the store itself. Source: our cleaned
   retailer/spell tables. A store authorized on Jan 1 t does not count.
2. **`dist_nearest_bigstore_mi`**: distance in miles to the nearest Supermarket or Super Store authorized on
   Jan 1 of t (excluding the store itself). Source: cleaned retailer/spell tables.
3. **`county_unemployment_rate`**: BLS LAUS county annual-average unemployment rate. Annual averages for year Y
   are released about April of Y+1, so **cohort t uses year t-2** (the t-1 annual average is not out by Jan 1 t).
   Files were downloaded by hand (bls.gov blocks scripts) from https://www.bls.gov/lau/tables.htm, County Data;
   source and checksums are recorded in `data/sources.yaml`.
   **Amendment (before any feature was built): it is an additional feature, not a replacement.** The tract-level
   ACS `unemployment_rate` stays (median-imputed, as now). Reason: the county rate is constant within a
   county-year, so it cannot rank stores within Mecklenburg, while the tract rate can.
   **Limitations:** (a) the county rate varies mainly over time, so it may echo batch-heavy years (a calendar-year
   proxy in effect, though the year itself is not a feature); (b) because cohort t uses year t-2, the 2020 COVID
   spike enters only in the 2022 test cohort, so the model never sees it in training or validation; (c) LAUS is
   revised and we only have the current revised series, so early-year values are not exactly what was published
   on the corresponding Jan 1.
4. **`fara_lilat_flag`**: USDA Food Access Research Atlas low-income / low-access flag (urban 1 mile / rural
   10 miles) for the store's tract, from the **latest Atlas release before Jan 1 of t**, with release dates taken
   from the Read Me sheets and recorded in `src/prep/reference/release_dates.csv`. Missing before the first
   release. **No missing-value indicator** is added if it would act as a year marker (missingness is
   year-determined).

### Evaluation (training folds only)

- Rolling folds inside 2012-2018 only; the same fold structure as the current model. Validation is **not**
  scored until approved.
- Run each configuration with the **current trees settings** and also with the **same tuning grid** as the
  current model.
- Report mean training-fold PR-AUC for: the current model (0.155); the model with all four features; and each
  feature added alone to the current feature set (add-one ablation; the ACS `unemployment_rate` stays in every model).

### Decision rule (step 4)

Adopt the new feature set only if its mean training-fold PR-AUC beats **0.155 by at least 0.005**. If it does,
score validation once and adopt only if validation PR-AUC is **not lower than 0.149**. Otherwise keep the current
model. Either way, the result is recorded here and the model is frozen. Test outcomes are never read.

## Model refinement (D4): demographics-free variant (pre-registered)

Written and committed before the variant was run. No re-tuning, no new features, test outcomes never read.

A variant without tract demographic features (pct_poverty, median_hh_income, pct_snap_hh, pct_no_vehicle, pct_renter,
unemployment_rate, pct_age_65_plus) is preferred if its mean training-fold PR-AUC is within 0.005 of 0.155; rationale:
less reliance on neighborhood demographics.

Protocol: frozen trees settings (lr 0.1, max_leaf_nodes 2, min_samples_leaf 100, l2 0, 300 iterations), `exit_12m`,
rolling folds inside 2012-2018 (fit 2012..k-1, score k, k = 2015-2018), same as the current model. Validation
(2019-2021) is reported for both versions (PR-AUC and the majority-Black vs majority-White false-positive rate, using
the top-50-per-year flag from `02_error_analysis.py`) but is **report only, not for selection**.

### Result and decision (fairness check)

Source: `docs/fairness_variant.md` (`src/model/04_fairness_variant.py`). Mean training-fold PR-AUC, folds 2015-2018, frozen settings:
with demographics **0.1549**, without **0.1486** (folds 0.100 / 0.157 / 0.202 / 0.135 vs 0.097 / 0.189 / 0.199 / 0.134). The variant needed
>= 0.150 and is 0.0014 short, so **the rule is not met: the current model with demographics is kept.**

Report only (validation 2019-2021, not used for selection): PR-AUC 0.149 with vs 0.162 without. Top-50-per-year false-positive rate,
majority-Black tracts: 4.1% with vs 4.6% without; majority-White: 1.5% with vs 1.2% without (29 and 131 validation exits respectively).
Dropping the demographics did not narrow the Black/White false-positive gap here (it widened slightly), so the validation numbers would not have
supported the rationale either; the rule was applied as written on the training folds.

### Bias finding (flag for the D6 test-set bias discussion)

Removing the seven tract demographic features did not reduce the majority-Black vs majority-White false-positive gap; it widened slightly
(top-50-per-year FPR, validation 2019-2021: Black 4.1% -> 4.6%, 31 -> 36 of 636 non-exits flagged; White 1.5% -> 1.2%, 81 -> 63 of 4,024).
Validation has 29 majority-Black and 131 majority-White exits, so these rates are noisy. Our reading is that the disparity is carried by
store-level features (store type, chain size, store age) whose distribution differs by tract, not by the demographic inputs. Supporting
descriptive counts (validation store-years): majority-Black tracts 665 (14.0% Small Grocery Stores, median chain size 13, median store age 13.3
years, exit rate 4.4%); majority-White tracts 4,155 (8.0% Small Grocery Stores, median chain size 44, median age 14.6 years, exit rate 3.2%).
The type and chain-size mixes differ; store age barely does, so it is not yet supported as a driver. **This attribution is an inference, not
tested** (no ablation of those store-level features was run). To address in D6 on the test set: report group FPRs with counts, and say that the
gap persists without demographic inputs and is plausibly mediated by store type and chain size.

features, test outcomes never read): (1) impact weights stay 0.5 / 0.25 / 0.25; (2) the Jan-1 distance to the nearest other grocery is a prep-pipeline

medium and high tiers; (4) the API pins the exact scikit-learn version and returns 503 if its startup self-check fails; (5) the app defaults to risk x impact
with a risk-alone option. Calibration: none applied (`docs/calibration.md`). Tiers: 0.021 / 0.084 (`docs/risk_tiers.md`).

Final model: refit on 2012-2021 with the frozen settings (`src/model/09_final_refit.py`; bundle in gitignored `models/`). Tier shares moved by at most 2.3
percentage points versus the 2012-2018 model (`docs/refit_tier_shares.md`). **The refit model cannot be evaluated on validation; its only evaluation is the
D6 test run.** The contract for the D4 builder is `docs/model_spec_d4.md`.
